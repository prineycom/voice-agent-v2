# I4 deterministic evidence: exact legacy adoption

## Outcome

A first `voice-agent install` now routes only the exact selected-new/running-old/no-previous legacy split into a launcher-owned adoption transaction. The exact healthy running release becomes ready legacy rollback custody, the selected legacy release remains not-ready/uncommitted evidence, and only a separately signed platform candidate can become canonical `current` after exact five-component readiness.

The adopter stages and SHA-256/CAS-checks the ignored mode-`0600` legacy service configuration without exposing values, writes absent disabled v2 defaults, and records the exact rootless user Docker endpoint only when explicit socket/owner/daemon evidence agrees. It performs no Docker or AgentEnvironment lifecycle action. Linger and the user unit are prepared while the legacy system service remains authoritative. Candidate failure restores and proves the old service; double failure retains recovery material.

## Deterministic acceptance

The canonical `./verify` launcher phase owns `launcher/test/adopt.test.cjs`. Disposable fixtures cover:

- the observed exact split and a compatible historical control while an incompatible application-manifest shape does not erase custody;
- exact legacy release/inventory, installed unit, MainPID/cgroup, cwd/executable/argv, runtime build/release, five-component readiness and loopback listener ownership mismatch refusal;
- ready prior import, not-ready selected import, signed candidate activation and legacy service retirement only after readiness;
- no-follow/mode/owner staged config copy, source/stage hashes, CAS, existing-canonical conflict refusal and byte-preserved secret prefix with zero output leakage;
- verified explicit rootless, rejected rootful/foreign, and honestly unavailable Docker records with no image/container/controller action;
- candidate success, candidate failure with exact prior readiness, and double-failure truth;
- injection after every observed durable write/action followed by convergence without duplicate stop/start/retire, config assignment, release import or container action.

The full canonical gate output is saved at `artifacts/legacy-adoption-verify.log`.

## Security and privacy

Durable adoption records contain opaque transaction/release IDs, digests, phases, booleans and stable failure codes only. Source paths, environment names/values, process argv, PIDs, Docker context/credentials and arbitrary host paths are not recorded or printed. Historical payloads are copied only from the exact owner/no-follow inventory and become read-only launcher custody. Rootful or foreign Docker never becomes a fallback.

## Nonclaims

This evidence uses only injected isolated roots, service/network/host facts and in-memory signed fixtures. It does not touch or claim the live stand, production signing/channel publication, real systemd or rootless Docker transition, AgentEnvironment migration/container preservation, network/model/GPU/reboot/voice/physical acceptance, removal of disabled legacy unit bytes, explicit rollback/uninstall/support bundle, launcher self-update or macOS support.
