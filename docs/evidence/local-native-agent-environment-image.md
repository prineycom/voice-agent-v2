## Contract

- `agent-environment/image-lock.v2.json` pins the base by digest and exact Dockerfile/helper bytes and original modes. The derived context revision is independent of a mutable Docker tag.
- `stand agent-image prepare` requires those original modes, rootless Docker, selects only the host-native `linux/amd64` or `linux/arm64` platform, invokes fixed `docker buildx build --load`, and freshly verifies exact image ID, platform, labels/context, namespace-root user, entrypoint/helper command and rootfs presence.

Before that inspection, one descriptor-checked owner creates or validates the complete product-private AgentEnvironment state root and empty Docker-client leaf at mode `0700`. It may safely narrow an existing same-user, non-writable, owner-private mode such as `0755`, while symlink, non-directory, foreign-owner, writable, cross-device or identity-drift custody fails before registry/Docker mutation. Inspect-only absent status exercises this same invariant without creating registry/container identity. Its Docker client explicitly sets only the derived endpoint and rejects ambient context/host/config/credentials plus missing, foreign, replaced, remote, system/rootful, incompatible, or changed endpoint/daemon custody without fallback. Endpoint failure stays content-free and distinct from actual prepared-image absence. Container inspection must report the same image ID; runtime contains no build, login, pull, push, publish, fallback or repair route.
- Enabled startup creates/starts and helper-validates exactly one persistent container before full readiness or action admission. The process is namespace root mapped by the admitted current-user rootless daemon to the ordinary host user; `cap-drop ALL`, `no-new-privileges`, explicit binds, no Docker socket and no rootful/host fallback remain unchanged. Writable `--mount` binds use Docker's default writable semantics; only RO declarations add `readonly`.
- Main/dev share the prepared immutable ID only. Their registries, containers, rootfs, workspace, cache, credentials and other mutable state remain instance-private.
