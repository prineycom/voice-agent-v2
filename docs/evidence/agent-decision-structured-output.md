There is no extraction, repair, coercion, retry, replay or fallback. Genuine HTTP structured-output rejection remains provider-global.

## Source-backed b10357 diagnosis

The separately authorized privacy-safe exact-runtime matrix identified `/props` build `b10357-689e227db`. Exact V4 and no-metadata V4 returned 4xx `grammar_parse_failed`. Changing only final `answer.maxLength` to 1999 or 2001, or removing only that annotation, returned 2xx; generated bytes were discarded. The 1999 probe retained metadata, `oneOf`, citations/pattern/other bounds, generic arguments and the tool enum, disproving them as the trigger. Minimal schemas and direct GBNF also returned 2xx, with unit restart delta zero.

This matches upstream llama.cpp issue [#27087](https://github.com/ggml-org/llama.cpp/issues/27087): `{0,2000}` is rejected at `MAX_REPETITION_THRESHOLD=2000` because the clamp uses `>` while the parser rejects `>=`; 1999 and 2001 pass. Related issue [#25746](https://github.com/ggml-org/llama.cpp/issues/25746) records the nested `maxLength:2000` grammar-parse failure class. The live matrix proves the exact pinned binary is affected; upstream issue version claims are supporting, not substitutive, evidence.
