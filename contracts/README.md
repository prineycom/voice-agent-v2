# Contract ownership

These machine-readable contracts are executable controller seams. Historical V1 media/inference and E1/E2.2/E2.3 files remain immutable evidence. E2.4 adds active `agent-config.v2`, restart-pinned `agent-runtime-status.v2`, `public-operational-status.v2`, AgentRun/decision/operation/result/budget/realtime/cancellation v1, and AgentEnvironment status/call receipt v1. E3.1 supersedes only the AgentEnvironment status and call receipt with binary-safe, persistence-matrix-aware v2; E3.2 extends those active v2 shapes with fixed credential-name modes, network/stream bounds, authority warning, and acknowledgement/no-retry truth. E3.3 adds the opaque `agent-process-receipt.v1` seam and extends strict V2 config/status with typed additional mounts, process/lifecycle bounds, conflict disclosure, and retained-generation truth. E4.1 adds `agent-run.v2`/`agent-decision.v2` and `research-citation.v1`; E4.2 adds `agent-run.v3`/`agent-decision.v3` plus `saved-report.v1`, `telegram-delivery.v1`, and `telegram-delivery-status.v1`; E4.3 supersedes the active seam with `agent-run.v4`/`agent-decision.v4`, revisioned `saved-report.v2`, `report-artifact-revision.v1`, `report-artifact-operation.v1`, `telegram-delivery.v2`, and honest-boundary status v2. Historical v1 stays pre-research, v2 pre-delivery, and v3 pre-update. They are owned directly by `voice_agent_v2.agent_environment_config`, `agent_run`, `agent_environment`, `agent_report_delivery`, and the web gateway; there is no generic runtime layer. [`docs/architecture.md`](../docs/architecture.md#5-contracts-and-ownership) remains authoritative.

| Contract | Owner | Producer → consumer | Limits and terminal semantics |
| --- | --- | --- | --- |
| `event-envelope.v1` | Session controller | Session controller → trace consumer | Every observation carries the same bounded session/turn IDs, all contract versions, and a contiguous sequence. A turn ends in exactly one `turn.completed`, `turn.failed`, or `turn.interrupted`; nothing follows it. Optional diagnostic timestamps are not part of normalized evidence. |
| `stt.v1` | STT seam | Session controller ↔ deterministic STT | Slice-local PCM is mono signed 16-bit little-endian at 16 kHz and at most 1 MiB per request. A final transcript or an explicit hard failure advances/ends the turn; failure fabricates no transcript. |
| `llm-provider.v1` | Session controller/provider adapter seam | Session controller ↔ deterministic fake provider | Request/response text is bounded to 4096 characters. `deterministic-fake` is only the Slice 1 fixture identity; the real selected adapter reuses this controller seam under the [provider boundary](../docs/architecture.md#51-llm-provider-boundary). Provider failure fabricates no answer and sends nothing to TTS. |
| `tts.v1` | TTS seam | Session controller ↔ deterministic TTS | Text is bounded to 4096 characters. PCM chunks are ordered from zero, each is at most 64 KiB, and share the declared format. Failure emits no audio; cancellation emits no chunks after interruption. |
| `realtime-control.v1` | Session controller | Session controller → browser | Reliable LiveKit data messages carry bounded session/turn IDs, a connection epoch, one session-wide increasing sequence, closed event types, lifecycle order, and terminal semantics. The browser drops wrong-version/session/epoch/turn, duplicate, late, out-of-order, oversized, and malformed input before UI actions. `turn.completed` means local generation finished and all accepted PCM frames were submitted to the persistent server media source; it does not depend on browser playback observations or prove physical playback, audibility, microphone operation, or barge-in timing. |
| `client-control.v1` | Session controller | Browser → session controller | The sole admitted control is a bounded, increasing, current-epoch-correlated reconnect notice. Browser playback and autoplay observations are telemetry only; no media acknowledgement participates in turn correctness. Duplicate, late, malformed, wrong-session/epoch, and unknown client events are dropped. |
| `tts.v2` | TTS service | Session controller ↔ model-neutral local TTS adapter | Session/epoch/turn/turn-generation/request/segment identity, closed adapter capabilities, plain shaped text, explicit mono `pcm_s16le/48000`, ordered ≤64-KiB worker chunks, exact samples/bytes/duration, and one terminal outcome. Active composition contains only Silero `v5_5_ru` / `kseniya`; V1 remains unchanged. |
| `event-envelope.v2` | Session controller | Real controller → realtime bridge | Preserves STT/LLM v1 while selecting TTS v2 and carrying stream epoch, turn generation, and request ID through every internal event. |
| `realtime-control.v2` | Session controller | Session controller → browser | Adds turn/request/output-media generation and `turn.media-ready`. The browser attaches the persistent publication only for the matching current generation, suspends it on a valid current interruption, and ignores invalid/old controls. Before any successful `turn.listening`, an enriched hard `turn.failed` for publication with `livekit_unavailable` and `admit_turn: false` is the only valid first turn terminal; the browser reconstructs that failed turn directly. Slice 8 uses the bounded payload for typed health, failure disposition, timing, provider, count, and resource metadata without adding another event bus. Reliable topic is `voice-agent.control.v2`. |
| `observation.v1` | Session controller observability boundary | Services/controller/browser adapters → outside-Git metadata JSONL | One monotonically sequenced, session/turn-correlated scalar-only observation. Keys that can contain raw media, transcript, prompt, response, secrets, tokens, or content identifiers are rejected; specific count/timing names are allowlisted. Size/file/age limits and write-failure counts are explicit. |
| `health-readiness.v1` | Session controller observability boundary | Server capability owners → controller/browser System panel | Separate liveness, readiness, contract/artifact compatibility, identity, reason, and bounded recovery attempts for exactly five records—one for each hard server capability. The browser combines that report with the existing avatar-host health boundary to render the avatar host and active module as two additional System rows. Fixed local/provider/auth/wake/avatar facts are closed and validated. |

The JSON Schema files are checked by `./verify` using the dependency-free validator. The executable `validate_tts_v2_document` semantic boundary complements the schema with ordered chunk and exact PCM total relationships that JSON Schema cannot express. Python `Protocol` definitions and `src/voice_agent_v2/realtime.py` exercise the producer/consumer ownership without requiring LiveKit or network access. The contained JSON-lines transport is separately versioned `voice-agent.silero-worker.v1`: its request and every response carry and validate that exact internal version rather than claiming to be the public TTS v2 document shape.

## Fixture policy

- Published versioned fixtures remain immutable. V1 media/inference fixtures are historical; the active Slice 8 observation/readiness fixtures are also V1, while active TTS/event/control examples are V2.
- `fixtures/traces/*.jsonl` are canonical normalized public traces for success, injected hard failures, and cancellation.
- `fixtures/pcm-hashes.json` declares the raw generated PCM identities and format. PCM bytes are regenerated, not stored as recordings.
- Changing a contract, fixture, or tracer without updating the others makes `./verify` fail.
- `launcher/fixtures/` contains canonical bounded artifact/channel bytes and detached signatures; `launcher/keys/` contains a public fixture key only. `launcher/tools/sign-fixture.cjs` signs deterministic canonical fixtures only with an explicitly supplied external test key and neither generates nor provisions production signing material. Fresh-install tests generate an ephemeral in-memory Ed25519 pair and discard it with the process; no generated private key is written or tracked.
